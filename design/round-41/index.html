Tokens

One source: kit41.css. The mock reads the tokens; the QML column is the device equivalent. The cluster runs Qt 5.14 on eglfs with the Mali GPU (/etc/qtenv.sh), so transform, opacity, and colour animate on the GPU.

TokenValueQMLUse
--m-fast120 msduration: 120Alert in, small exits, colour changes
--m-base200 msduration: 200Moves: focus, cruise arrow, chips, switches, segment pill

--m-smooth120 ms time constantBehavior { SmoothedAnimation { velocity: -1; duration: 240 } }Continuous readings: speed bar, rpm and boost bands, steering arc, cruise arrow, brake meter
--m-slide56 pxx offsetLargest slide distance
--ease-outcubic-bezier(.33, 1, .68, 1)Easing.OutCubicEvery enter and move
--ease-incubic-bezier(.32, 0, .67, 0)Easing.InCubicEvery exit
  • Animate transform (translate, scale, rotate), opacity, and colour only. Layout (width, height, anchors) never animates: the brake meter fill scales from the left edge.
  • Enter with ease-out, exit with ease-in. An exit is shorter than the matching enter, except for a warning: the warning enters within 120 ms and leaves over 200 ms.
  • A warning never waits for an animation. Telltales and the turn signal flash keep the existing timing.
  • Numbers snap to each new sample (speed digits, rpm, boost, set speed, brake output). The gauge that shows the same value moves smoothly between samples (10 Hz on the mock).
  • The vendor QML smoothed the speed value itself (a commented-out Behavior on vehicleSpeed), which also delayed the digits. The spec smooths only the gauge position.

Card page change: A or B

A slides the old page out and the new page in, in the page order (56 px, 120 ms out, 280 ms in). B crossfades (120 ms out, 200 ms in). Recommendation: A. The direction tells the driver which way the page moved, and a jump on a trailer brake or a climb reads as a page change, not a flicker.
